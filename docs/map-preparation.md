# 地图按需处理与依赖校验

## 使用方式

地图页面按游戏列出游戏档案（profile），并保留现有的地图显示、3D 道路和处理速度设置。

- 游戏、档案的自动维护开关同时开启，档案才可以发起自动校验和准备。新项目及升级后的默认值都是关闭。
- 关闭游戏开关不会清除档案选择，也不会删除已有地图。重新打开游戏开关后恢复原来的档案选择。
- “准备一次”只处理明确选择的目标，不修改维护开关；批量选择弹窗初始不勾选任何目标。
- 默认先校验依赖；“强制重建”明确跳过校验，执行完整生成。
- 首次设置可以选择“稍后准备”。地图尚未准备不阻止使用其他功能。
- TruckersMP 和已发现的 ProMods 服务器地图分别选择；这里的“存档”指游戏档案，不是自动存档槽。

关闭维护的目标只读取列出档案、计算组合身份和寻找已有缓存所需的信息，不打开它的 mod 包或校验地图依赖。实时路口导航独立按需读取当前游玩档案的资源，不依赖地图维护开关；Steam Cloud 档案同样使用游戏文档目录下的 mod。多个档案的游戏、地图和有效 mod 组合相同，仍共享任务和结果；未启用的档案不会另行发起任务。界面会说明共享关系。

目标标识由游戏种类、规范化档案目录及 TruckersMP 变体组成，不依赖显示名称或缓存目录。缓存目录另按游戏种类、安装目录、地图和有序 mod 包标识隔离。

## 缓存状态与兼容

缓存可用性、自动维护选择、任务状态分别提供给前端。有缓存时继续显示地图，并在车机中提示可能过期；没有缓存时显示“尚未准备”。

旧地图缺少依赖记录时标记“未验证”，不会因为升级或仅打开自动维护而立即重建。用户需要主动准备一次建立基线。无法读取的可选资源或跳过的 mod 会保留明确的未验证状态，不能冒充最新地图。

每个档案保存最后可用的地图引用。同一游戏、同一地图可以在 mod 组合改变时暂用之前的缓存；切换到另一独立地图或另一游戏时不会回退到无关地图。最后可用缓存与执行中任务的输出不会因关闭维护而清理。

## 什么时候真正重建

生成时在虚拟文件系统访问层记录实际查询，随 `map.json` 原子提交带版本的依赖记录：

- 普通文件内容、纹理像素或顶层纹理数据；普通读取也覆盖间接引用的定义、模型和预制件。
- 文件缺失的查询结果，以及排序后的文件、子目录枚举结果。
- 使用 SHA-256 比较当前挂载优先级最终返回的结果，不比较压缩算法、包内偏移或单独的整包时间戳。

游戏完整版本、DLC 名单、mod 大小及高精度修改时间只是校验线索。只有实际依赖结果、地图标识、有效语言、影响结果的生成器版本或 ATS guard 解析结果变化才需要完整生成。所有有效 mod 都进入实际挂载顺序，避免仅按“地图 mod”分类漏掉材质、模型覆盖。

文件夹 mod 的线索包括子文件和目录的元数据，不能只依赖根目录修改时间。同一进程内有界的摘要缓存按资源来源和元数据复用；没有变化的资源不反复解压。校验仍重新解析覆盖来源，能发现新增、删除和原本缺失的文件出现。

生成时跳过或缺失的 mod 与其状态摘要、提示一起写入地图清单；状态改变（包括缺失的 mod 重新出现）后保守重新处理。可选资源无法可靠验证时，产物可继续使用，但显示未验证。校验或生成期间输入改变则重新检查，不将混合输入发布为最新。

本次没有实现道路、图块局部增量更新。确认需要重建时仍执行现有完整流程。

## 调度和取消

继续保持最近游玩的档案优先、游戏关闭后生成、内存不足等待的规则。

取消接口按任务 ID 操作。关闭自动维护移除排队任务；运行中的自动任务若已无已选消费者则取消；显式一次性任务不受开关影响。正式构建终止对应生成子进程，开发回退使用停止令牌，不停止整个地图监视服务，也不影响后续任务。

取消的输入签名和最后可用缓存引用保存在 `maps/preparation-state.json`。相同输入跨重启不会自动重试；普通存档写入不清除取消记录。手动准备可以重试，相关输入变化后重新评估。

每个任务通过独立决定文件仲裁取消与提交。先写新资源和依赖记录，最后替换地图清单。取消先获胜则保留旧清单、清理本次未完成资源；提交先获胜则不能再取消已提交结果。过期任务 ID 不能取消后来的任务。

## 接口

- `prepare_maps({ targets: string[], force: boolean })`：非空且已知的明确目标。
- `prepare_maps_again({ targets: string[] })`：保留命令名的显式强制重建入口。
- `cancel_map_preparation({ taskId: string })`：只取消指定任务，返回是否成功取消。
- 显示状态附带 `target`、`autoEnabled`、`gameAutoEnabled`、`hasCache`、`cacheState`、`taskId`、`reason` 和 `sharedTargets`。

不存在以空参数或 `folders: null` 隐式处理全部游戏的服务入口。

## 验证与性能日志

PowerShell 构建沿用仓库完整 LLVM-MinGW 工具链，仅设置当前进程的 `CC`、`AR`，无需修改系统环境：

```powershell
$env:WESTPLAY_LLVM_MINGW = (Resolve-Path target/toolchains/llvm-mingw-20260602-ucrt-x86_64).Path
$env:CC = Join-Path $env:WESTPLAY_LLVM_MINGW 'bin/clang.exe'
$env:AR = Join-Path $env:WESTPLAY_LLVM_MINGW 'bin/llvm-ar.exe'
cargo check --workspace --locked
cargo test -p westplay-mapdata -p westplay-setup -p westplay-host --lib --locked
cargo test -p westplay-mapdata --test dependencies --locked -- --nocapture --test-threads=1
cargo clippy -p westplay-host -p westplay-setup -p westplay-mapdata --all-targets --locked
npm --prefix ui test -- --maxWorkers=2
npm --prefix ui run lint
npm --prefix ui run build
```

宿主日志分别记录校验耗时、实际重读的查询数与字节数、复用次数，以及是否调用完整生成。读取字节数是查询返回的解压/解码结果及目录名称字节量，不等于底层磁盘 I/O 量。完整生成另记录总耗时与是否发布。

2026-11-12 的真实 ZIP 合成样本：更换归档内顺序、存储方式改为 Deflate、修改未读取的音频后，依赖校验约 3.7–11.3 ms（多次测试运行），首次读取 2 个查询、25 字节，第二次复用 2 个查询；未调用完整生成。随后改变道路内容会检测到变化。这个小样本只证明跳过生成与复用路径，不能推算真实 ETS2/ATS 或大型 mod 组合的提速倍数。

最终验证结果：Rust 三个相关 crate 的库测试 583 项通过、50 项保留忽略，依赖集成测试 8 项通过（共 591 项通过）；前端 84 个文件、501 项测试通过。工作区 `cargo check`、相关 crate 的 Clippy、前端 lint、TypeScript 检查及生产构建均通过，现有 lint 警告与 Vite 大包提示保留。界面检查覆盖游戏/档案默认关闭、准备一次、按任务取消、批量空选择、向导稍后准备及窄窗口布局。

构建及测试日志存放于 Git 忽略的 `target/map-prepare-*.log`。未生成安装包，未部署到游戏目录。
